# 매뉴얼 음성 도우미 — 기획서

> 원본: `매뉴얼_음성_도우미_기획서.docx` (개인 포트폴리오)
> **한 줄 정의** — 가전·전자기기 사용 중 생긴 질문을 음성으로 물으면, 제품 매뉴얼을 검색해 정확한 답을 음성으로 안내하는 핸즈프리 RAG 시스템

## 1. 프로젝트 개요

### 1.1 배경 및 문제 정의
가전제품이 갑자기 멈추거나 에러코드가 뜨면 사용자는 대부분 PC가 아니라 손에 든 스마트폰으로 해결책을 찾는다. 그러나 제조사 매뉴얼은 수십 페이지 분량의 PDF로 제공되어, 정작 급할 때 필요한 한 줄짜리 답("UE 에러는 세탁물 한쪽 쏠림")을 찾기까지 시간이 걸린다. 또한 양손이 기기를 만지고 있는 상황에서는 화면을 스크롤하며 검색하기 어렵다.

본 프로젝트는 이 사용 맥락 — 폰을 들고, 고장난 가전 앞에서, 음성으로 묻는 상황 — 에 맞춰, 매뉴얼을 근거로 정확한 답을 음성으로 돌려주는 모바일 웹앱을 제안한다.

### 1.2 목표
- **사용자 가치**: 매뉴얼을 직접 뒤지지 않고 음성 한 번으로 정확한 사용법·에러 조치를 안내받는다.
- **기술 목표**: 도메인 문서 기반 RAG 파이프라인을 단계적으로 고도화하고, 검색 정확도를 정량 평가하며, 실패 유형을 클러스터링해 약점을 분석한다.
- **포트폴리오 목표**: "벡터 검색 + LLM 래퍼"를 넘어, 검색 품질을 수치로 증명하고 개선 과정을 보여주는 ML 엔지니어링 역량을 입증한다.

### 1.3 차별점
기존 매뉴얼 검색 앱은 키워드 검색 또는 단순 챗봇 수준에 머문다. 본 프로젝트의 핵심 차별점은 매뉴얼이라는 '정답 페이지가 명확한' 도메인 특성을 활용해 검색 품질을 객관적으로 평가하고 개선하는 데 있다.

## 2. 핵심 기능
1. **음성 질의 입력** — 마이크 버튼으로 "세탁기 UE 에러 떴어" 같은 자연어 질문을 음성으로 입력.
2. **제품·기종 식별** — 질문에서 제품군과 모델을 파악해 검색 범위를 좁힌다.
3. **매뉴얼 근거 검색** — 해당 매뉴얼에서 질문과 가장 관련된 페이지·섹션을 검색·재순위.
4. **근거 기반 답변 생성** — 검색된 내용을 바탕으로 답을 생성하고, 출처 매뉴얼 페이지를 함께 표시.
5. **음성 응답** — 생성된 답변을 음성으로 재생해 핸즈프리로 따라 할 수 있게 한다.
6. **출처 표시** — 답변과 함께 근거가 된 매뉴얼 위치를 보여줘 환각 여부를 확인 가능.

## 3. 시스템 아키텍처
시스템은 **실시간 추론 파이프라인**과 **오프라인 평가 모듈**로 구성된다. 추론 파이프라인이 실제 서비스 흐름이고, 평가 모듈이 포트폴리오의 핵심 차별점을 담당한다.

### 3.1 실시간 추론 파이프라인
음성 질문(STT) → 제품·기종 식별 → 매뉴얼 RAG 검색 → LLM 답변 생성 → 음성 응답(TTS). 답변에는 출처 매뉴얼이 함께 표시된다.

### 3.2 데이터 파이프라인
매뉴얼 PDF는 사전에 한 번 인덱싱해 검색 가능한 형태로 준비한다.
- **① 오프라인 인덱싱**: 매뉴얼 PDF → 파싱·청킹(페이지·섹션 메타데이터 부착) → 한국어 임베딩 → 벡터 DB 저장
- **② 온라인 추론**: 질문 임베딩 → Top-k 검색·재순위 → 컨텍스트 구성 → 근거 기반 답변 생성

### 3.3 RAG 3단계 (점진적 고도화)
| 단계 | 구성 | 핵심 |
|------|------|------|
| Naive | 단순 임베딩 Top-k 검색 | 베이스라인 |
| Hybrid + Reranker | BM25 + 임베딩 결합 후 재순위 | 키워드·의미 결합으로 정확도 향상 |
| Agentic | 모델 식별·재질의·다단계 검색 | 복합 질문 대응, 검색 실패 시 재시도 |

## 4. 평가 설계 (포트폴리오 핵심)
매뉴얼은 "이 질문의 정답은 몇 페이지"가 명확히 정해지는 도메인이다. 추천 시스템과 달리 검색 정확도를 객관적 수치로 측정할 수 있고, 이것이 본 프로젝트를 기술적으로 차별화하는 핵심이다.

### 4.1 평가셋 자동 생성
- 매뉴얼 본문을 바탕으로 LLM이 "질문 ↔ 정답 페이지/섹션" 쌍을 자동 생성.
- 질문 유형을 의도적으로 분산: **에러코드형 · 사용법형 · 사양·수치형 · 문제해결형** 등.
- 생성된 평가셋은 일부 수기 검수로 품질을 보정.

### 4.2 정량 지표
- **Recall@k**: 정답 페이지가 상위 k개 검색 결과에 포함되는 비율
- **MRR (Mean Reciprocal Rank)**: 정답이 몇 번째로 검색되는지의 역순위 평균
- **단계별 비교**: Naive → Hybrid+Reranker → Agentic 순으로 위 지표 개선 측정

### 4.3 실패 클러스터링 (차별 포인트)
단순히 점수만 내는 데서 그치지 않고, 어떤 질문에서 시스템이 엉뚱한 페이지를 찾는지를 유형별로 분류한다. 예: '에러코드형은 잘 찾지만 사양·수치형에서 정확도가 급락' 같은 약점을 정량적으로 드러내고 개선 근거로 삼는다. 면접에서 "검색 품질을 어떻게 진단하고 개선했는가"를 설명하는 핵심 스토리.

## 5. 기술 스택
| 영역 | 후보 기술 | 비고 |
|------|----------|------|
| 프론트엔드 | 모바일 웹앱 (반응형) / 필요 시 PWA | 폰 브라우저에서 즉시 실행, 설치 불필요 |
| STT | Whisper (로컬 GPU) 또는 CLOVA Speech | 한국어 음성 인식 |
| 임베딩 | 한국어 특화 임베딩 모델 | 매뉴얼 청크 벡터화 |
| 검색 | BM25 + 벡터 검색 + Reranker | Hybrid 검색 구성 |
| LLM | API 또는 로컬 모델 | 근거 기반 답변 생성 |
| TTS | CLOVA Voice 또는 XTTS 계열 | 답변 음성 합성 |
| 문서 처리 | PDF 파싱 · 청킹 · 인덱싱 파이프라인 | 오프라인 전처리 |

## 6. 데이터 확보 전략
매뉴얼 PDF가 시스템의 '정답지' 역할을 하므로 데이터 확보가 프로젝트 성패의 핵심.
- 제조사 공식 사이트에서 대표 카테고리의 매뉴얼 PDF 수집 (세탁기, 에어프라이어, 에어컨, 전자레인지 등으로 범위 한정).
- 초기에는 카테고리를 좁게 시작해 인덱싱·평가 파이프라인을 검증한 뒤 점진적으로 확장.
- 평가셋은 수집한 매뉴얼 기반으로 LLM 자동 생성 + 수기 검수로 구축.

## 7. 개발 일정 (2개월)
| 주차 | 주요 작업 | 산출물 |
|------|----------|--------|
| W1–2 | 매뉴얼 수집 · PDF 파싱 · 청킹/인덱싱 · Naive RAG 베이스라인 | 검색 가능한 벡터 DB, 베이스라인 검색 |
| W3 | 평가셋 자동 생성 · Recall@k/MRR 측정 환경 구축 | 평가 노트북, 베이스라인 점수 |
| W4–5 | Hybrid + Reranker 구현 · 단계별 성능 비교 | 개선된 검색기, 비교 결과 |
| W6 | 실패 클러스터링 · 질문유형별 약점 분석 | 실패 분석 리포트 |
| W7 | STT/TTS 연동 · 모바일 웹앱 UI 구현 | 동작하는 음성 웹앱 |
| W8 | Agentic RAG · 통합 · 데모 정리 · 문서화 | 최종 데모, 포폴 정리 |

## 8. 기대 효과
- **사용자 측면**: 1인 가구·기기 초보 사용자의 가전 문제 해결 진입장벽을 낮춘다.
- **기술 측면**: 도메인 RAG 파이프라인 설계, 검색 품질 정량 평가, 실패 분석이라는 ML 엔지니어 핵심 역량 입증.
- **확장성**: 동일한 "음성 + 도메인 RAG + 실패 분석" 뼈대를 다른 도메인(법령, 의약품 등)에 도메인만 교체해 재사용 가능.
